HOW THE INTEGRITY CHECK WORKS
--------------------------------------------------------------------------------

The application verifies its branding at startup and then periodically while
the desktop app is running. Six layers are checked:

  1. In-memory constants  - the attribution is re-derived from primitives and
                            compared against the canonical string and its
                            SHA-256 seal.
  2. On-disk manifest     - tfast-brand.json records the SHA-256 of every
                            protected file.
  3. Manifest self-seal   - the manifest carries its own seal over its body, so
                            editing the recorded hashes is caught too.
  4. Source watermark     - bl.py and gui.py must still contain the
                            "@brand tfast-digital" marker.
  5. Import-hijack check  - the loaded brand module must be the real file on
                            disk, not a stub injected into sys.modules.
  6. Copyright notice     - tfast-NOTICE.txt must still name TFast Digital
                            Agency.

If any check fails, the application refuses to start (exit code 3) and names
the failing file. That refusal is intentional and is not a defect.

Protected by hash:
    bl_core/tfast_brand.py
    bl_core/branding.py        (compatibility shim)
    bl_core/tfast_guard.py
    tfast-NOTICE.txt
    assets/tfast.ico

Checked by watermark:
    bl.py
    gui.py

RE-SEALING AFTER A LEGITIMATE CHANGE
------------------------------------
If you intentionally change a protected file (for example to update the
copyright year), re-seal the build so the check accepts your change:

    python tools/tfast_seal.py

    python tools/tfast_seal.py --check   # verify only
    python tools/tfast_seal.py --list    # show what is covered
